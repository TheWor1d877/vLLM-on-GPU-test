| 模型 / hash | Qwen2.5-7B-Instruct；model-00001 sha256 a1333e62…1966aba7，00002 f5d25a27…cd0ea6185，00003 8efdec4c…81bcdfd5，00004 1a72d403…3faf879bd |

负载口径：输入 512 token（固定种子随机 token id），输出强制 128 token（ignore_eos + max_tokens），每档 40 条请求双跑，温度 0。760 条请求全部恰好输出 128 token，0 失败 0 截断。

## 核心结论
| 指标 | 值 |
|---|---|
| 经济并发点 | 32（测试范围内未饱和，吞吐随并发近线性增长） |
| 吞吐上限（tokens/s） | 1476.6（并发 32） |
| 32 并发相对 8 并发的吞吐增益 | +132.0% |
| 32 并发 TTFT P99 中排队占比 | 0.9%（0.99 / 108.0 ms） |
| 压小 KV 池后的抢占次数 | 7（KV 池压到 10240 token） |

## 显存占比
服务启动后总占用 36755 MB（35.89 GiB），空闲基线 14 MB。权重与 KV 池取 vLLM 启动日志实测值，其余归激活与上下文碎片。

| 项 | GiB | 占比 |
|---|---|---|
| 模型权重 | 14.29 | 39.8% |
| KV 块池 | 20.35 | 56.7% |
| 激活与上下文碎片 | 1.25 | 3.5% |

KV 块池容量 381008 token（gpu-memory-utilization 0.9）。现象 A 用 `--num-gpu-blocks-override 640` 压到 10240 token，同时 `--max-model-len 8192`（0.33 启动校验要求池子装得下一条 max_model_len 序列）。

## 现象观测
| 现象 | 结论 | 关键数字 |
|---|---|---|
| A 限制 KV 池触发抢占 | 池容量不足时调度器抢占重算，排队主导延迟 | 抢占 7 次；TTFT P50/P99 2747 / 2937 ms；排队 P99 2969 ms；吞吐 789.3 tok/s |
| B 长时运行漂移 | 并发 16 连发 200 条，后半程延迟抬升 | ITL 前半 14.0 → 后半 15.0 ms（+6.9%）；TTFT 213.1 → 274.4 ms；吞吐 951.5 tok/s |
| C FP16 与 AWQ 同并发对比 | AWQ 走 Marlin 内核，无回退；权重减半换来更大 KV 池与更高吞吐 | 并发 8 吞吐 636.5 → 948.2 tok/s（+49.0%）；KV 池 381008 → 548080 token；日志确认 Using MarlinLinearKernel |
